# コード解説

コードの仕組みをわかりやすく説明する。中高生にも分かる言葉で。

## 手順

### ステップ1: 対象の種類を判定

$ARGUMENTS を読んで、何を説明するか判定する:

| 対象の種類 | 例 | 説明の重点 |
|-----------|-----|-----------|
| 関数 | `src/utils/auth.ts:login` | 入力→処理→出力の流れ |
| ファイル | `src/api/users.ts` | ファイルの責務と公開API |
| モジュール | `src/hooks/` | モジュール間の関係と責務分担 |
| データフロー | 「ログインの流れ」 | ユーザー操作からDB保存までの全経路 |
| アーキテクチャ | 「全体構成」 | レイヤー構成と依存関係 |

$ARGUMENTS が空の場合: 「何を説明しますか？」とファイルツリーを見せて選んでもらう。

### ステップ2: コードを読む

1. 対象のコードを読む
2. 関連するファイル（import先、呼び出し元）も読む
3. テストがあればテストも読む（使い方の参考になる）

### ステップ3: 解説を出力

以下のフォーマットで出力する:

```
## 一言で言うと
[このコードは何をするか、1文で]

## データフロー図
[入力] → [処理1] → [処理2] → [出力]
     ↓           ↓
  [副作用1]   [副作用2]

## ステップ解説
1. まず○○が起きる
   - コード: `ファイル:行`
   - なぜ: この処理が必要な理由
2. 次に○○する
   ...

## ハマりポイント
- [注意すべき箇所と理由]

## 関連ファイル
| ファイル | 役割 |
|---------|------|
| src/xxx.ts | [このファイルとの関係] |
```

### ステップ4: 難易度に応じた調整

| 複雑さ | 調整 |
|--------|------|
| シンプル（1関数、20行以内） | 一言 + コード内コメントで十分 |
| 中程度（1ファイル、複数関数） | 全フォーマットで説明 |
| 複雑（複数ファイル、非同期処理） | シーケンス図を追加 |

複雑な非同期処理がある場合:
```
Client    Server    DB
  |--POST-->|        |
  |         |--SELECT-->|
  |         |<--rows----|
  |<--200---|        |
```

## エッジケース

| 状況 | 対処 |
|------|------|
| 対象が見つからない | 似た名前のファイル/関数を提案 |
| 外部ライブラリの内部 | 「このライブラリは○○をする」で留める |
| コードが難読化されている | その旨を伝える |
