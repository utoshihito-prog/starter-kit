# AGENTS.md

## 最優先ルール（絶対に守ること）

1. **スキルを使え**: ユーザーが `/スキル名` と言ったら、対応するスキルファイルを読んでその手順に従え。自己流で代替するな
2. **勝手に進めるな**: 各フェーズの成果物は人間に見せて承認を得てから次へ進め
3. **一度に全部やるな**: 1フェーズ = 1ステップ。brainstorm と spec と plan を同時に作るな

## フェーズゲート（飛ばすな）

```
[Brainstorm] → 人間が承認 →
[Spec]       → 人間が承認 →
[Plan]       → 人間が承認 →
[Execute]    → 差分ごとに検証 →
[Review]     → 人間が確認 →
[Ship]
```

**禁止事項:**
- docs/spec.md が人間に承認されるまで plan を作るな
- plans/*.md が人間に承認されるまで実装コードを書くな
- テストが通らないままコミットするな
- 人間が「進めて」と言うまで次フェーズに行くな

**例外:** 人間が「全部一気にやって」と明示した場合のみ、フェーズを飛ばしてよい

## スキルの使い方

スキルファイルはエディタごとに以下の場所にある:
- Claude Code: `.claude/skills/スキル名/SKILL.md`
- Gemini CLI / Antigravity: `.gemini/skills/スキル名/SKILL.md`
- Cursor: `.cursor/skills/スキル名/SKILL.md`
- Windsurf: `.windsurf/skills/スキル名/SKILL.md`
- Codex: `.agents/skills/スキル名/SKILL.md`

**スキル実行手順:**
1. 該当するスキルファイルを読む
2. スキルの手順に書いてある通りに実行する
3. スキルに定義された出力フォーマットで結果を出す
4. 手順を飛ばさない。省略しない

## ルール

- まず計画を立てる。複数ファイルを変える作業、設計変更、一文で説明できない作業は必ず plan を作ってから実装する
- 最小の正しい差分を出す。動いてるコードを理由なく書き直さない
- 成功を宣言する前に検証する。scripts/verify.sh があればそれを使う
- 既存のパッケージマネージャとタスクランナーに従う。勝手にツールを変えない
- 必要なければ依存パッケージを追加しない
- 生成ファイル、ロックファイル、マイグレーション、シークレット、CI設定はタスクが要求しない限り触らない
- 動作・設計・ワークフロー・テスト方針が変わったら docs/ を更新する
- 迷ったら docs/ を読んでからコードを触る

## コンテキスト管理

- コンテキスト使用率は40%以下を維持する
- 40%を超えたらタスクをまとめて新セッションを開始する
- コンテキストの長さを理由にショートカットしない。タスクは完全に終わらせる
- 途中で切り上げるくらいなら、新しいセッションを提案する
- 1タスク = 1セッションが基本。タスクが変わったら新しい会話を始める
- 大量のトークンを消費する操作の前に「これは大量のコンテキストを消費します。続けていいですか？」と聞く

## 安全境界

慎重に扱う領域（人間の確認なしに変更しない）:
- 認証・認可・課金・権限
- DB schema / migration
- 依存パッケージの追加
- CI/CD パイプライン
- 本番環境の設定・シークレット
- 検証できない変更がある場合は、何が未検証かを明示する

- 古くなったルールは削除する
