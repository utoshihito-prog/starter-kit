# AGENTS.md

## 最優先ルール（絶対に守ること）

1. **スキルを読んで従え**: ユーザーの発言に該当するスキルがあれば、スキルファイルを開いてその手順通りに実行しろ。自己流でやるな
2. **勝手に進めるな**: 各フェーズの成果物は人間に見せて承認を得てから次へ進め
3. **一度に全部やるな**: 1フェーズ = 1ステップ。spec と plan と実装を同時に作るな
4. **テンプレートを自分で埋めるな**: `{{...}}` が残っているファイルは `/auto` または初回起動時にユーザーと一緒に埋める。勝手に推測しない

## ユーザーの発言 → やること対応表

ユーザーがこう言ったら、対応するスキルファイルを読んでその通りに動け。
自己判断で「似たようなこと」をするな。必ずスキルを読め。

| ユーザーの発言 | 読むスキル |
|--------------|-----------|
| 「とりあえずやって」「進めて」「お任せ」 | `auto` |
| 「仕様書を作って」 | `spec` |
| 「計画して」「タスクに分けて」 | `plan` |
| 「テスト書いて」「TDD で」 | `tdd` |
| 「整理して」「リファクタ」 | `refactor` |
| 「バグ調べて」「動かない」 | `diagnose` |
| 「テスト作って」 | `test-gen` |
| 「レビューして」 | `review` |
| 「セキュリティ見て」 | `security-check` |
| 「シンプルにして」 | `polish` |
| 「コミットして」 | `commit` |
| 「PR作って」 | `pr` |
| 「テスト通してpush」「リリース」 | `land` |
| 「引き継ぎ作って」 | `handoff` |
| 「引き継ぎから再開」 | `resume` |
| 「/スキル名」 | そのスキル |

スキルファイルの場所はエディタごとに異なる:
- Claude Code: `.claude/skills/スキル名/SKILL.md`
- Codex: `.agents/skills/スキル名/SKILL.md`
- Gemini CLI: `.gemini/skills/スキル名/SKILL.md`

## 初回（プロジェクトに初めて触る時）

1. このファイルを最後まで読む
2. ユーザーに「何をしますか？」と聞く
3. ユーザーの回答に対応するスキルを上の表から探して実行する

**禁止: docs/ のテンプレートを見て勝手に穴埋めを始めること。ユーザーの指示を待て。**

## フェーズゲート（飛ばすな）

```
[Spec]    → 人間が承認 →
[Plan]    → 人間が承認 →
[Execute] → 差分ごとに検証 →
[Review]  → 人間が確認 →
[Ship]
```

**禁止事項:**
- docs/spec.md が人間に承認されるまで plan を作るな
- plans/*.md が人間に承認されるまで実装コードを書くな
- テストが通らないままコミットするな
- 人間が「進めて」と言うまで次フェーズに行くな

**例外:** 人間が「全部一気にやって」と明示した場合のみ、フェーズを飛ばしてよい。ただし破壊的操作・設計の分岐・認証/課金/DBスキーマ変更は例外なく確認を取る。

## ルール

- まず計画を立てる。複数ファイルを変える作業は必ず plan を作ってから
- 最小の正しい差分を出す。動いてるコードを理由なく書き直さない
- 成功を宣言する前に検証する。scripts/verify.sh があればそれを使う
- 既存のパッケージマネージャとタスクランナーに従う
- 必要なければ依存パッケージを追加しない
- 動作・設計・ワークフロー・テスト方針が変わったら docs/ を更新する
- 迷ったら docs/ を読んでからコードを触る

## コンテキスト管理

- コンテキスト使用率は40%以下を維持する
- 40%を超えたらタスクをまとめて新セッションを開始する
- 途中で切り上げるくらいなら、新しいセッションを提案する
- 1タスク = 1セッションが基本

## 安全境界（人間の確認なしに変更しない）

- 認証・認可・課金・権限
- DB schema / migration
- 依存パッケージの追加
- CI/CD パイプライン
- 本番環境の設定・シークレット
