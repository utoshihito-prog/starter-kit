# 依存パッケージ監査

プロジェクトの依存パッケージの問題をチェックする。

## 手順

### ステップ1: パッケージマネージャーの検出

| ファイル | パッケージマネージャー | 監査コマンド |
|---------|-------------------|------------|
| package-lock.json | npm | `npm audit` |
| pnpm-lock.yaml | pnpm | `pnpm audit` |
| yarn.lock | yarn | `yarn audit` |
| requirements.txt | pip | `pip audit` (要インストール) |
| Pipfile.lock | pipenv | `pipenv check` |
| go.sum | Go | `govulncheck ./...` |
| Cargo.lock | Cargo | `cargo audit` |

### ステップ2: 脆弱性チェック

1. 検出した監査コマンドの実行を提案する
2. コマンドが使えない場合はインストール方法を案内する
3. 結果をパースして重要度別に整理する

### ステップ3: アップデートチェック

1. `npm outdated` / `pip list --outdated` 等でバージョン情報を取得する
2. Semver リスク評価:

| アップデート種類 | リスク | 対応 |
|---------------|--------|------|
| パッチ (1.0.0→1.0.1) | 低 | すぐ更新OK |
| マイナー (1.0→1.1) | 低〜中 | CHANGELOGを確認して更新 |
| メジャー (1.x→2.x) | 高 | 破壊的変更あり。テスト必須 |

### ステップ4: 未使用パッケージの検出

1. インストール済みパッケージのリストを取得する
2. プロジェクト内のimport/require文を検索する
3. import されていないパッケージを検出する
4. ただし以下は誤検出しやすいので注意:
   - 設定ファイルで使うパッケージ（eslint, prettier等）
   - CLI ツール（typescript, prisma等）
   - Peerドependencies

### ステップ5: ライセンスチェック

商用利用で問題になるライセンスを検出する:
- GPL系（コードの公開義務）→ 警告
- AGPL（サーバーサイドでも公開義務）→ 強い警告
- MIT, Apache-2.0, BSD → 問題なし

### ステップ6: 結果を出力

```
## 依存パッケージ監査結果

### 脆弱性
| パッケージ | バージョン | 重要度 | 脆弱性 | 修正バージョン |
|-----------|----------|--------|--------|-------------|
| lodash | 4.17.20 | HIGH | プロトタイプ汚染 | 4.17.21 |

### アップデート推奨
| パッケージ | 現在 | 最新 | 種類 | リスク |
|-----------|------|------|------|--------|
| next | 14.0 | 14.2 | マイナー | 低 |
| react | 18.2 | 19.0 | メジャー | 高 |

### 未使用の可能性
| パッケージ | 理由 |
|-----------|------|
| moment | import が見つからない |

### アクション
1. `npm install lodash@4.17.21` — 脆弱性修正（即時）
2. `npm install next@14.2` — マイナーアップデート（推奨）
3. `npm uninstall moment` — 未使用パッケージ削除（確認後）
```

## エッジケース

| 状況 | 対処 |
|------|------|
| lockファイルがない | 「lockファイルがありません。`npm install` を先に実行してください」 |
| 監査コマンドが使えない | インストール方法を案内 |
| プライベートレジストリ | 監査が効かない旨を伝える |
| モノレポ | 各パッケージのworkspaceごとにチェック |
