# チーム進捗確認

> **このスキルの役割**: チーム開発モード（/team-start）での役割別進捗確認専用。
> チーム開発モードを使っていない場合は /progress を使う。

roles/ と tasks.md を読んで、役割別の進捗を報告する。

## 手順

### ステップ1: チーム構成の確認
1. roles/ ディレクトリが存在するか確認する
2. **存在しない場合**: 「チーム開発モードが設定されていません。/team-start で始めるか、/progress で全体進捗を確認してください」と案内して終了
3. roles/ の全ファイルを読んで役割一覧を取得する

### ステップ2: 担当別の進捗を計算
1. tasks.md の各タスクの担当タグ `[frontend]` `[backend]` 等を解析する
2. タグがないタスクは「未割り当て」としてカウントする
3. 役割別の完了率を計算する

### ステップ3: ダッシュボードを表示

```
==============================
  チーム進捗状況
==============================
  architect:  ██████████ 100% (2/2)  全体設計完了
  frontend:   ████░░░░░░  40% (2/5)  トップページ作業中
  backend:    ██████░░░░  60% (3/5)  API認証完了
  designer:   ██████████ 100% (3/3)  デザイン完了
------------------------------
  全体:       ██████░░░░  67% (10/15)
------------------------------
  ブロック: なし
  次の優先: フロント - お問い合わせページ
==============================
```

### ステップ4: ブロックの検出
- 他の担当待ちで進められないタスクを検出する
- 例: 「backend の API が完了しないと frontend のデータ表示が進められない」
- ブロックがあれば警告表示する

### ステップ5: tasks.md の進捗サマリーを更新

## エッジケース

| 状況 | 対処 |
|------|------|
| roles/ がない | /progress を案内 |
| 担当タグがないタスクが多い | 「担当が未割り当てのタスクがX件あります。割り当てますか？」と提案 |
| 1人の担当がボトルネック | 「[担当]のタスクが残り最多です。タスクの再配分を検討してください」と提案 |
