# 開発再開

HANDOFF.md を読んで状況を把握し、開発を再開する。

## 手順

### ステップ1: 引き継ぎ資料を探す

以下の優先順位で情報を集める:

1. HANDOFF.md が存在するか確認する → あれば読む
2. なければ docs/tasks.md を確認する → あれば読む
3. なければ docs/architecture.md を確認する → あれば読む
4. **どれもない場合**:
   - `git log --oneline -20` で最近の作業を把握する
   - コードベースを走査して主要ファイルを特定する
   - 「引き継ぎ資料がありません。コードから状況を推測します」と伝える

### ステップ2: 現在の状態を要約して表示

```
==============================
  プロジェクト状況
==============================
  全体進捗:  ████████░░ 80% (12/15)
  最終コミット: feat: 検索機能を追加 (2日前)
  最終タスク: 検索機能の実装
------------------------------
  注意点:
  - APIのレート制限が未実装
  - テストカバレッジが低い (40%)
==============================
```

### ステップ3: 次にやるべきタスクを提示

1. docs/tasks.md の未完了タスクを一覧する
2. 優先度順に並べる（HANDOFF.md の優先順があればそれに従う）
3. 最初に着手すべきタスクを推薦する

### ステップ4: 確認

「以上が現在の状況です。最初のタスクから始めていいですか？」と確認してから作業開始する。

## エッジケース

| 状況 | 対処 |
|------|------|
| HANDOFF.md も tasks.md もない | git log + コード走査で状況を推測。タスク一覧の作成を提案 |
| tasks.md が全部完了済み | 「全タスクが完了しています。次のフェーズを計画しますか？」 |
| プロジェクトが壊れた状態 | テスト実行で問題を特定。修正を最優先タスクにする |
