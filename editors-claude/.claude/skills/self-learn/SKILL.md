# パターン学習

「毎回やってる作業」をgit履歴やコードから見つけてスキルにする。

> **注意**: セッション履歴には直接アクセスできません。
> git履歴・コードパターン・ユーザーへのヒアリングから推測します。

## 手順

### ステップ1: git履歴からパターンを検出

1. `git log --oneline -50` で直近50コミットを取得する
2. 以下のパターンを探す:

| パターン | 検出方法 | 例 |
|---------|---------|-----|
| 同じ種類のファイルが一緒に変更される | コミットごとの変更ファイルを分析 | .ts と .test.ts が常にセット |
| 繰り返しのコミットメッセージ | メッセージのパターンを分析 | 「fix: lint エラーを修正」が5回 |
| 定型的なファイル追加 | 新規ファイルのパターン | 毎回同じ構造のコンポーネントを追加 |

### ステップ2: コードからパターンを検出

1. プロジェクト内のファイルを走査する
2. 以下を検出:

| パターン | 検出方法 | スキル化の例 |
|---------|---------|------------|
| コピペコード | 類似構造のファイルが3つ以上 | テンプレート生成スキル |
| 定型ボイラープレート | 同じimport + 同じ構造のファイル | scaffold スキル |
| 手動で繰り返す手順 | scripts/ 内のシェルスクリプト | 自動化スキル |

### ステップ3: ユーザーへのヒアリング

git とコードから見つけたパターンに加えて、ユーザーに聞く:

「以下のパターンを検出しました。他に毎回やっていることはありますか？」

1. 検出したパターンを一覧表示する
2. ユーザーが追加のパターンを教えてくれたらリストに追加する

### ステップ4: パターンカードの作成

各パターンを以下のフォーマットで評価する:

```
## パターン: [名前]

| 項目 | 内容 |
|------|------|
| 発生回数 | X回（直近50コミット中） |
| 手作業の手間 | 毎回約X分 |
| 自動化可能性 | 高/中/低 |
| スキル化の価値 | ★★★☆☆ |

### 現在の手順
1. ...
2. ...

### スキル化した場合
- コマンド: /[スキル名]
- 節約時間: 毎回約X分
```

### ステップ5: スキル化の実行

1. スキル化の価値が★3以上のパターンを提案する
2. ユーザーが承認したら /save-skill でスキルを作成する
3. 作成後「/[スキル名] で使えます」と案内する

## スキル化の基準

| 基準 | 閾値 |
|------|------|
| 発生回数 | 3回以上 |
| 手作業の時間 | 毎回2分以上 |
| 手順の定型度 | 毎回ほぼ同じ手順 |

3つ全て満たすパターンのみ提案する。

## エッジケース

| 状況 | 対処 |
|------|------|
| 新規プロジェクト（コミット少ない） | 「まだ履歴が少ないです。しばらく開発してから再実行してください」 |
| パターンが見つからない | 「明確な繰り返しパターンは検出されませんでした」で終了 |
| 既にスキル化済み | 「これは /[既存スキル名] と同じでは？」と確認 |
