# Auto Mode — 賢く自動進行

ユーザーの依頼を分類し、適切なスキルを順に呼び出してゴールまで走る。**ただし要所で必ず人間に確認を取る。**

## 入力分類

ユーザー発話から下記のいずれかに分類する。曖昧なら1度だけ聞き返す。

| 種別 | 例 | パイプライン |
|------|------|---------|
| 新機能 | 「ログイン機能を作って」 | `/spec` → 確認 → `/plan` → 確認 → 実装 → `/review` → `/commit` |
| バグ修正 | 「ログインできない」 | `/diagnose` → 確認 → 修正 → `/test-gen` → `/commit` |
| リファクタ | 「ここを整理して」 | `/refactor` → `/review` → `/commit` |
| レビュー | 「コード見て」 | `/review` → 必要なら `/security-check` |
| 出荷 | 「リリースして」 | `/test-gen` 確認 → `/commit` → `/pr` → `/land` |
| 引き継ぎ | 「引き継ぎ作って」 | `/handoff` |
| 不明 | — | 1度だけ「何がしたいか」を聞く |

## 確認ゲート（必ず止まる）

連続実行するが、**以下の場合は必ず手を止めてユーザーに見せる**:

1. **破壊的操作の前** — ファイル削除 / `git reset --hard` / force push / 本番DB変更
2. **設計の分岐** — 技術選定 / DBスキーマ変更 / 認証・課金まわり
3. **想定スコープ超過** — 計画にない変更が必要になった時
4. **テスト失敗** — 自動修正を試みる前に状況を報告
5. **各フェーズ完了時** — Spec / Plan / 実装ブロック / レビュー / Ship 直前

確認は短く: 「◯◯やります。OK？」の1行。

## 進行原則

- **1スキル1コミット** を基本。途中で迷ったら止まる
- **コンテキスト節約** — 大量の調査は sub-agent (Explore / general-purpose) に分離
- **失敗時はロールバック** — 黙って隠さない。状態を報告して指示を仰ぐ
- **ログを残す** — 主要決定は `plans/` か `docs/decisions.md` に追記

## 起動メッセージ

```
🤖 Auto Mode 開始
依頼: {ユーザー入力の要約}
分類: {種別}
予定: {呼び出すスキル列}
要所での確認: 有効
```

## 終了メッセージ

```
✅ 完了
やったこと: {1-3行}
触ったファイル: {一覧}
次の推奨: {あれば}
```

## エッジケース

- **依頼が複合的** → 最も大きい1つから着手し、残りは `docs/tasks.md` に追記
- **既存計画がある** → `plans/` の最新を読み、それに従う
- **autopilot 的に全部丸投げ** → ユーザーが明示的に「全部やって、確認いらない」と言った時のみ、設計分岐・破壊的操作以外の確認を省略
