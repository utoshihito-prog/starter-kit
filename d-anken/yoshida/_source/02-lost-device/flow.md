# 端末再貸与対応フロー（盗難・紛失）

## 概要

本フローは、企業が法人契約で利用している端末（iPhone / iPad / Android / ガラケー等）の盗難・紛失が発生した際の、交換対応の手順を定義したものです。
利用者による事案報告から、紛失時対応依頼書の提出、交換品の手配・キッティング・発送、利用者の受領、および賠償金通知までの一連の流れを網羅しています。

---

## 登場人物（スイムレーン）

| レーン | 説明 |
|--------|------|
| **利用者** | 実際に端末（iPhone / iPad / Android / ガラケー等）を業務で使用している社員。盗難・紛失の当事者 |
| **企業管理者** | 法人契約の管理担当者。東日本・西日本支社の総務担当者など。利用者とK（ヘルプデスク）の窓口をつなぐ役割 |
| **K（ヘルプデスク）** | N（携帯会社）から**再委託を受けている代理店**。依頼書の確認、交換品の手配指示、キッティング（端末の初期設定）、MDM操作代行、受付管理簿の管理などを担当 |
| **N（営業担当）** | **携帯会社側の正規の顧客対応窓口（営業担当）**。盗難紛失で喪失したSIMカード／eSIMの再発行相談のほか、新規端末の導入やソリューション提案など、あらゆるオーダーの窓口を担当する。顧客にとっての正式な対応窓口であるため、代理店（K）からの情報共有が必須であり、常にCCに入る |
| **N（レンタルセンター）** | 携帯会社側の**物流・端末管理拠点**。交換品の在庫管理・発送、賠償金通知を担当 |

## フロー詳細

### Phase 1：事案発生〜依頼書提出

#### このPhaseで登場する用語

| 用語 | 説明 |
|------|------|
| **紛失時対応依頼書** | 端末の盗難・紛失に伴う交換対応をN（レンタルセンター）に依頼するための申請書（Excel形式） |
| **遺失届（受理番号）** | 警察署に盗難・紛失を届け出た際に発行される受付番号。依頼書の提出に先立ち取得しておく必要がある。「警視庁行政手続オンライン」サイトでの電子申請時は警察署名の記載は不要で受理番号のみ記載する（例：遺セ（電子）第●●●●号）。社内紛失等で遺失届ができない場合は、理由を記載した経緯書（会社印押印のもの）を提出する |
| **ABM（Apple Business Manager）** | Apple社が提供する法人向けの端末管理ツール。MDMと連動して、Appleアカウント・端末・アプリケーションを一元管理できる。主に一般企業が利用する |
| **ASM（Apple School Manager）** | Apple社が提供する教育機関向けの端末管理ツール。ABMの教育機関版で、学校や大学などが生徒・教職員のApple端末やアカウント、教材アプリを一元管理するために利用する。機能的にはABMとほぼ同等だが、教育機関専用のApple IDの管理や教材配布機能など教育向けの機能が含まれる |
| **SIMカード（UIMカード）** | 端末に挿入する小さなICカード。電話番号や契約情報が記録されており、これがないと通話・通信ができない。依頼書上では「UIMカード」と表記される。盗難紛失で端末ごとSIMカードを喪失した場合は、N（営業担当）が再発行手続きを行う。再発行手数料は3,850円（税込）※2025年9月5日以降は4,950円（税込）に改定。ただし盗難紛失を伴うeSIM再発行については手数料不要 |
| **eSIM** | 端末本体に内蔵された電子的なSIM。物理的なカードの差し替えが不要で、プロファイル（設定データ）をダウンロードして開通する。盗難紛失時はN（営業担当）がeSIMの再発行手続きを行う |

#### フロー

1. **【利用者】事案発生**
   - 業務で使用しているiPhone / iPad / Android / ガラケー等の盗難または紛失が発生する

2. **【利用者→企業管理者】盗難/紛失の事案報告** 📧
   - 利用者が自社の企業管理者（総務担当など）に、端末の盗難・紛失を報告する
   - 報告内容の例：端末の機種名、紛失場所・時期、盗難・紛失の経緯など

3. **【企業管理者】適宜社内処理 / 依頼書作成** （注1）
   - 企業管理者が社内の承認手続きなどを行ったうえで、「**紛失時対応依頼書**」（Excel形式）を作成する
   - 記入項目：申込年月日、契約者名（フリガナ）、依頼元部署名・連絡先電話番号・メールアドレス、依頼元ご契約代理人様名、ABM/ASM（DEP）組織ID、交換機器送付先（住所・企業名・部署名・担当者名・電話番号）、届出日/警察署名、遺失届受理番号、盗難・紛失場所・時期、紛失物品情報（レンタル端末名・製造番号・色・容量・利用電話番号）、UIMカード再発行の要否、紛失時賠償金へのポイント利用有無、キッティング情報（情報1〜4）

4. **【企業管理者→K（ヘルプデスク）】依頼書提出** 📧
   - 作成した「紛失時対応依頼書」をExcelファイルのままメールでK（ヘルプデスク）に送付する

> **備考：** 依頼書には承諾事項・確認事項が記載されている。交換機器は同一機種同一色が原則だが、ソフトウェア・OSバージョンは保証されず、未使用品に限らずクリーニング・初期化済み端末を含む場合がある。本体のみの発送で、付属品は別途購入が必要。賠償金はレンタルあんしん補償オプション加入時は無料、未加入時は所定の負担金額が発生する。通常版は社印または依頼元ご契約代理人様自署の上PDF送付、決裁番号取得版は決裁番号記入によりExcelのまま送付可能。

#### このPhaseの注記

| 注番号 | 内容 |
|--------|------|
| 注1 | 依頼時に警察への遺失届番号が必要となるため、事前に受理番号を取得していることが前提となる。紛失確定後には「紛失時対応依頼書」を送付する。海外で紛失した場合は渡航履歴が判るもの（パスポートの出入国の写し・往復航空券のコピー等）を依頼書と合わせて提出する。SIMカード/eSIMカード再発行はN（営業担当）へ相談 |

### Phase 2：受付〜不備確認

#### このPhaseで登場する用語

| 用語 | 説明 |
|------|------|
| **不備確認** | 依頼書の記載内容に誤り・漏れがないかチェックする作業。記入漏れ、契約名義と実際の契約の不一致、機種名の誤り、送付先住所の不備などを確認する |
| **ABM/ASM組織ID** | ABMまたはASM上で各企業に割り振られている固有の識別番号。交換品のキッティング時に「この端末をどの企業のABM/ASM環境に登録するか」を特定するためのキーとなる情報。K（ヘルプデスク）がキッティング工程でABM上のデバイス割り当てやMDMへの紐づけを行う際に必須となるため、ABM/ASMを利用している企業は依頼書に必ず記入する必要がある |

#### フロー

5. **【K（ヘルプデスク）】受付**
   - 依頼書をメールで受領し、盗難紛失の交換対応を開始する

6. **【K（ヘルプデスク）】不備確認**
   - 依頼書の記載内容に不備がないかをチェックする
   - **不備あり** → 企業管理者へ差し戻し（修正依頼）
   - **不備なし** → 次のステップ（受付管理簿）へ進む
   - チェック項目の例：記入漏れ、契約名義と実際の契約の一致、機種の正確性、ABM/ASM組織IDの記載有無（ABM/ASM利用企業の場合、キッティング時のデバイス割り当てに必須のため未記入だと作業が進められない）、遺失届受理番号の記載有無など

7. **【企業管理者】返却 / 修正**（不備ありの場合）
   - K（ヘルプデスク）から指摘された不備箇所を修正し、依頼書を再送付する

> **備考：** 「紛失時対応依頼書」に不備があるか確認し、必要に応じてお客様に連絡します。
> - 記入漏れ
> - 契約名義/機種確認
> - など

### Phase 3：受付管理簿〜交換品手配

#### このPhaseで登場する用語

| 用語 | 説明 |
|------|------|
| **受付管理簿** | 企業ごとに作成される、故障交換をはじめとする各種依頼を一元管理するための台帳（Excel形式）。管理簿は「受付管理簿」シート、「リスト」シートの2シートで構成される。受付管理簿シートの主な管理項目は、項番（通し番号）、受付日、キャンセル有無、携帯電話番号、受付区分、発送日、伝票番号、完了日、故障/紛失対応情報（レンタル品管理No.、故障機の機種名・製造番号、申告内容・症状、交換品の機種名・製造番号）、メモ欄/備考。受付区分（受付種別）はおおまかに「故障」「紛失・盗難」「リクエストキッティング」「MDM代行操作」「ABM/ASM代行操作」の5種類で分類される（案件や企業の契約形態によって細分化・変動する場合がある）。リストシートは受付管理簿シートの「受付区分」をドロップダウンで選択するためのもの |
| **MDM代行操作** | ※MDMの種類によって文言や機能に差分あり。主な代行操作の項目としては、<br>**デバイス削除：** 不要な端末のデータをMDMから削除する。<br>**プロファイル変更/削除：** 端末に配信する制限プロファイル等の内容を変更したり、削除する。<br>**アプリ配信/削除：** 新たにアプリを追加配信したり、不要なアプリを削除する。<br>**ユーザ登録/変更/削除：** ユーザ情報を新規で追加したり、既存のデータを修正したり、削除する |
| **ABM/ASM代行操作** | 主な代行操作の項目としては、<br>**MDMとデバイスの紐づけ/解除：** 顧客が契約しているMDMと端末を紐づけすることでADE（Automated Device Enrollment [旧称：DEP]）の機能を使用したり、別のMDMと紐づけるために現状のMDMとの紐づけを解除する。<br>**所有状態の解除：** 二度とその企業で同じ端末を利用しない場合に管理下から削除する。教育機関や学校などで使用していた端末を利用者（生徒）が卒業に伴ってプライベート端末に転用する場合などに使う。N（携帯会社）では、レンタル品をセンターに返却する際にほかの企業で転用するために、対象企業の所有状態を外す目的で使用する |

#### フロー

8. **【K（ヘルプデスク）】受付管理簿 更新**
   - 受付管理簿に依頼内容を記録する
   - 記録項目：受付日、携帯電話番号、受付区分（盗難紛失フローの場合は「紛失・盗難」を選択）、紛失機のレンタル品管理No.・機種名・製造番号、申告内容・症状など
   - 交換品の発送後に発送日・伝票番号・交換品の機種名・製造番号を追記し、対応完了時に完了日を記録する

9. **【K（ヘルプデスク）→企業管理者】承り連絡** 📧
   - 依頼を正式に受け付けたことを企業管理者にメールで通知する（依頼元メールへの全返信）
   - これにより企業管理者は「依頼が受理された」ことを確認できる

10. **【企業管理者】確認**
    - 承り連絡の内容を確認する

11. **【K（ヘルプデスク）→N（レンタルセンター）】交換品手配** 📧
    - レンタルセンターに対し、交換用端末の準備・発送を依頼する

12. **【N（レンタルセンター）】確認**
    - K（ヘルプデスク）からの依頼内容（機種・送付先など）を確認する

### Phase 4：交換品準備〜キッティング実施

#### このPhaseで登場する用語

| 用語 | 説明 |
|------|------|
| **キッティング** | 交換用の端末を利用者が業務で使える状態にセットアップする作業のこと。MDMプロファイルの投入、業務アプリの設定、各種ポリシーの適用、動作確認などを含む。端末の機種だけでなく、各企業・各部署ごとにキッティングの仕様（インストールするアプリ、適用する設定、制限ポリシーなど）が異なるため、依頼書のキッティング情報欄を参照して個別に対応する |
| **キッティング手順書** | キッティング作業の手順をまとめたマニュアル。端末の機種ごとだけでなく、各企業・各部署のキッティング仕様が異なるため、対象に応じた個別の手順書を印刷して作業に使用する |
| **MDM（Mobile Device Management）** | 企業が社員の端末を遠隔で一括管理するためのシステム。端末の設定配布、アプリ管理、紛失時のリモートロック・ワイプなどが可能。盗難紛失時には紛失した端末のライセンスを「デバイス削除」して管理対象から外す必要がある。盗難紛失時は絶対ではないが、MDM上にゴミデータ（使われていない端末の管理情報）が残る原因となり、開発元も削除を推奨している。また、MDMの種類によってはライセンス数に応じた課金体系のものがあるため、不要なライセンスを残すとコスト増につながる点にも注意が必要 |

#### フロー

13. **【N（レンタルセンター）→K（ヘルプデスク）】交換品発送** 📦
    - レンタルセンターから交換品をK（ヘルプデスク）に発送する

14. **【K（ヘルプデスク）】受領** 📦
    - レンタルセンターから届いた交換品を受け取る

15. **【K（ヘルプデスク）】交換品準備**
    - 交換品および発送時に必要な物品を適宜準備する

> **備考：** 交換品および発送時に必要な物品を適宜準備します。
> - テプラ貼付（管理番号ラベルの貼り付け）
> - 同梱物の封入
> - ※本体のみの発送。付属品（充電器、ライトニングケーブル、フィルムなど）は同梱されないため、最寄りのショップ等で別途購入が必要

16. **【K（ヘルプデスク）】キッティング稼働確保**
    - キッティング作業を実施するための人員・時間を確保する

17. **【K（ヘルプデスク）】キッティング手順書印刷 / キッティング準備** 📄
    - 該当企業・該当機種に応じたキッティング手順書を印刷し、キッティング作業の準備を行う

18. **【K（ヘルプデスク）】盗難/紛失機MDMデバイス削除** 🌐
    - **MDM操作代行：** 盗難・紛失した端末のライセンスを「デバイス削除」し、MDM管理対象から外す。デバイス削除を行う主な理由は以下の2点。①MDMの種類によってはライセンス数に応じた課金体系のものがあるほか、MDMから配信しているアプリ（Office 365などの有料アプリ）にもライセンス費用がかかるものがあるため、不要なライセンスを残すとコスト増につながる。②削除しないとMDM上にゴミデータ（使われていない端末の管理情報）が残る原因にもなり、開発元も削除を推奨している

19. **【K（ヘルプデスク）】交換品キッティング実施** （注2）
    - 交換用端末に対して**キッティング**を実施する
    - 依頼書のキッティング情報欄および該当企業のキッティング仕様に基づき、MDMプロファイルの投入、業務用アプリのインストール、各種設定の適用、動作確認などを行う

#### このPhaseの注記

| 注番号 | 内容 |
|--------|------|
| 注2 | 交換品の初期不良があった場合は、K（ヘルプデスク）にて交換品の再手配を行い、その旨を顧客へご連絡する |

### Phase 5：発送〜利用者受領

#### このPhaseで登場する用語

| 用語 | 説明 |
|------|------|
| **物理SIM** | 従来型のSIMカード。端末のトレイに差し込んで使用する。盗難紛失で端末ごと喪失した場合は、N（営業担当）がSIMカードの再発行手続きを行う |
| **プロファイルダウンロード** | eSIM利用時に、通信事業者から設定データを端末にダウンロードして通信を開通させる操作 |

#### フロー

20. **【K（ヘルプデスク）】交換品発送準備** 📦
    - キッティング完了済みの交換品について、発送のための梱包・伝票準備を行う

21. **【K（ヘルプデスク）→企業管理者】発送連絡** 📧
    - 交換品を発送した旨をメールで通知する（承り連絡メールへの全返信）

22. **【企業管理者】確認**
    - 発送連絡の内容を確認する

23. **【K（ヘルプデスク）】受付管理簿 更新**
    - 受付管理簿に発送日・伝票番号・交換品の機種名・製造番号を記録する

24. **【K（ヘルプデスク）→利用者】発送** 📦
    - 交換用端末を宅配便で利用者（または企業管理者経由）に発送する

25. **【利用者】受領** 📦
    - 宅配便で届いた交換品を受け取る

26. **【利用者】適宜データコピー 等**（任意）
    - 依頼後に盗難・紛失した端末が見つかった場合は、必要に応じて旧端末から交換端末へのデータコピー（連絡先・写真・ファイル等の移行）を行う。実施しなくても問題ない

> **備考（SIM開通状態について）：**
> - **eSIMご利用の場合：** 交換品はeSIM再発行（開通）済みの状態で発送される
> - **物理SIMご利用の場合：** 交換品はSIMカード再発行済みの状態で発送される

27. **【利用者→企業管理者】受領連絡** 📧
    - 交換品を受け取った旨を企業管理者に連絡する

28. **【企業管理者】受領**
    - 利用者からの受領連絡を確認する

### Phase 6：賠償金通知（条件付き）

> ※ 警察署に盗難・紛失の届出を行っていない場合など、所定の条件を満たさない場合に発動するフローです。

#### このPhaseで登場する用語

| 用語 | 説明 |
|------|------|
| **賠償金通知** | 盗難・紛失時に所定の条件を満たさない場合（遺失届未提出など）にN（レンタルセンター）から届く賠償金の請求通知 |
| **紛失時賠償金** | レンタルあんしん補償オプション加入時は無料。未加入時は、初期契約期間は割引前レンタル料総額、再レンタル期間は1回目3,000円（税抜）・2回目以降は割引前レンタル料総額が請求される（2019年10月以降契約分は申込書記載の通り） |

#### フロー

29. **【N（レンタルセンター）→K（ヘルプデスク）】賠償金通知** （注3）📧
    - 遺失届が未提出の場合など、所定の条件に該当する場合にN（レンタルセンター）がK（ヘルプデスク）へ賠償金通知を送付する

30. **【K（ヘルプデスク）】確認** （注4）
    - N（レンタルセンター）からの通知内容を確認する

31. **【K（ヘルプデスク）→企業管理者】転送** 📧
    - N（レンタルセンター）からの賠償金通知を企業管理者に転送する

32. **【企業管理者】賠償金通知 連絡受領** 📧
    - 賠償金通知を受領し、通知内容を確認する。社内での対応を行う

33. **【N（営業担当）】情報共有** 📧 (CC)
    - 賠償金が発生している旨を、顧客の正式な対応窓口であるN（営業担当）が把握しておく必要があるため、一連の通知のやりとりがCCで共有される
