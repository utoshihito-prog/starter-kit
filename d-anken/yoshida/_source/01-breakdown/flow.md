# 故障対応フロー

## 概要

本フローは、企業が法人契約で利用している端末（iPhone / iPad / Android / ガラケー等）に故障が発生した際の、交換対応の手順を定義したものです。
利用者による故障報告から、交換品の受領・開通、故障機の返却完了までの一連の流れを網羅しています。

---

## 登場人物（スイムレーン）

| レーン | 説明 |
|--------|------|
| **利用者** | 実際に端末（iPhone / iPad / Android / ガラケー等）を業務で使用している社員。故障の当事者 |
| **企業管理者** | 法人契約の管理担当者。東日本・西日本支社の総務担当者など。利用者と携帯会社側の窓口をつなぐ役割 |
| **K（ヘルプデスク）** | 携帯会社（N）から**再委託を受けている代理店**。故障受付窓口として、依頼書の確認、交換品の手配指示、キッティング（端末の初期設定）、MDM/ABM操作代行、受付管理簿の管理などを担当 |
| **N（営業担当）** | **携帯会社側の正規の顧客対応窓口（営業担当）**。故障や盗難紛失で喪失したSIMカード／eSIMの再発行相談のほか、新規端末の導入やソリューション提案など、あらゆるオーダーの窓口を担当する。顧客にとっての正式な対応窓口であるため、代理店（K）からの情報共有が必須であり、常にCCに入る |
| **N（レンタルセンター）** | 携帯会社側の**物流・端末管理拠点**。交換品の在庫管理・発送準備、故障機の受領・検品、未返却時の督促を担当 |

## フロー詳細

### Phase 1：故障発生〜依頼書送付

#### このPhaseで登場する用語

| 用語 | 説明 |
|------|------|
| **故障交換機器送付依頼書** | 端末の故障交換をレンタルセンター（N）に依頼するための申請書（Excel形式） |
| **ABM（Apple Business Manager）** | Apple社が提供する法人向けの端末管理ツール。MDMと連動して、Appleアカウント・端末・アプリケーションを一元管理できる。主に一般企業が利用する |
| **ASM（Apple School Manager）** | Apple社が提供する教育機関向けの端末管理ツール。ABMの教育機関版で、学校や大学などが生徒・教職員のApple端末やアカウント、教材アプリを一元管理するために利用する。機能的にはABMとほぼ同等だが、教育機関専用のApple IDの管理や教材配布機能など教育向けの機能が含まれる |
| **SIMカード（UIMカード）** | 端末に挿入する小さなICカード。電話番号や契約情報が記録されており、これがないと通話・通信ができない。依頼書上では「UIMカード」と表記される。故障交換時は旧端末からSIMカードを抜いて新端末に差し替えて使用する。盗難紛失で端末ごとSIMカードを喪失した場合は、N（営業担当）が再発行手続きを行う。再発行手数料は3,850円（税込）※2025年9月5日以降は4,950円（税込）に改定。ただし故障交換を伴うeSIM再発行については手数料不要 |
| **eSIM** | 端末本体に内蔵された電子的なSIM。物理的なカードの差し替えが不要で、プロファイル（設定データ）をダウンロードして開通する。eSIM端末の場合、故障交換時もSIMカードの差し替え作業は不要。盗難紛失時はN（営業担当）がeSIMの再発行手続きを行う |

#### フロー

1. **【利用者】事案発生**
   - 業務で使用しているiPhone / iPad / Android / ガラケー等に故障が発生する（画面割れ、電源が入らない、通信不良など）

2. **【利用者→企業管理者】故障の症状報告** 📧
   - 利用者が自社の企業管理者（総務担当など）に、端末の故障内容を報告する
   - 報告内容の例：端末の機種名、症状の詳細、発生日時など

3. **【企業管理者】適宜社内処理 / 依頼書作成** （注1）
   - 企業管理者が社内の承認手続きなどを行ったうえで、「**故障交換機器送付依頼書**」（Excel形式）を作成する
   - 記入項目：申込年月日、契約者名（フリガナ）、依頼元部署名・連絡先電話番号・メールアドレス、依頼元ご契約代理人様名、交換機器送付先（住所・企業名・部署名・担当者名・電話番号）、故障レンタル端末情報（対象機器・製造番号・色・容量・利用電話番号）、故障端末の状態・故障内容、ポイント利用有無、ABM/ASM利用時の組織ID、キッティング情報（情報1〜4）

4. **【企業管理者→K（ヘルプデスク）】依頼書送付** 📧
   - 作成した「故障交換機器送付依頼書」をExcelファイルのままメールでK（ヘルプデスク）に送付する

#### このPhaseの注記

| 注番号 | 内容 |
|--------|------|
| 注1 | 「故障交換機器送付依頼書」（Excel）を作成・送付。SIMカード/eSIMカード再発行はN（営業担当）担当へ相談 |

### Phase 2：受付〜不備確認

#### このPhaseで登場する用語

| 用語 | 説明 |
|------|------|
| **不備確認** | 依頼書の記載内容に誤り・漏れがないかチェックする作業。記入漏れ、契約名義と実際の契約の不一致、機種名の誤り、送付先住所の不備などを確認する |
| **ABM/ASM組織ID** | ABMまたはASM上で各企業に割り振られている固有の識別番号。交換品のキッティング時に「この端末をどの企業のABM/ASM環境に登録するか」を特定するためのキーとなる情報。K（ヘルプデスク）がキッティング工程でABM上のデバイス割り当てやMDMへの紐づけを行う際に必須となるため、ABM/ASMを利用している企業は依頼書に必ず記入する必要がある |

#### フロー

5. **【K（ヘルプデスク）】受付**
   - 依頼書をメールで受領し、故障交換対応を開始する

6. **【K（ヘルプデスク）】不備確認**
   - 依頼書の記載内容に不備がないかをチェックする
   - **不備あり** → 企業管理者へ差し戻し（修正依頼）
   - **不備なし** → 次のステップ（受付管理簿）へ進む
   - チェック項目の例：記入漏れ、契約名義と実際の契約の一致、機種の正確性、ABM/ASM組織IDの記載有無（ABM/ASM利用企業の場合、キッティング時のデバイス割り当てに必須のため未記入だと作業が進められない）など

7. **【企業管理者】返却 / 修正**（不備ありの場合）
   - K（ヘルプデスク）から指摘された不備箇所を修正し、依頼書を再送付する

> **備考：** 「故障交換機器送付依頼書」に不備があるか確認し、必要に応じてお客様に連絡します。
> - 記入漏れ
> - 契約名義/機種確認
> - など

### Phase 3：受付管理簿〜交換品手配

#### このPhaseで登場する用語

| 用語 | 説明 |
|------|------|
| **受付管理簿** | 企業ごとに作成される、故障交換をはじめとする各種依頼を一元管理するための台帳（Excel形式）。管理簿は「受付管理簿」シート、「リスト」シートの2シートで構成される。受付管理簿シートの主な管理項目は、項番（通し番号）、受付日、キャンセル有無、携帯電話番号、受付区分、発送日、伝票番号、完了日、故障/紛失対応情報（レンタル品管理No.、故障機の機種名・製造番号、申告内容・症状、交換品の機種名・製造番号）、メモ欄/備考。受付区分（受付種別）はおおまかに「故障」「紛失・盗難」「リクエストキッティング」「MDM代行操作」「ABM/ASM代行操作」の5種類で分類される（案件や企業の契約形態によって細分化・変動する場合がある）。リストシートは受付管理簿シートの「受付区分」をドロップダウンで選択するためのもの |
| **MDM代行操作** | ※MDMの種類によって文言や機能に差分あり。主な代行操作の項目としては、<br>**デバイス削除：** 不要な端末のデータをMDMから削除する。<br>**プロファイル変更/削除：** 端末に配信する制限プロファイル等の内容を変更したり、削除する。<br>**アプリ配信/削除：** 新たにアプリを追加配信したり、不要なアプリを削除する。<br>**ユーザ登録/変更/削除：** ユーザ情報を新規で追加したり、既存のデータを修正したり、削除する |
| **ABM/ASM代行操作** | 主な代行操作の項目としては、<br>**MDMとデバイスの紐づけ/解除：** 顧客が契約しているMDMと端末を紐づけすることでADE（Automated Device Enrollment [旧称：DEP]）の機能を使用したり、別のMDMと紐づけるために現状のMDMとの紐づけを解除する。<br>**所有状態の解除：** 二度とその企業で同じ端末を利用しない場合に管理下から削除する。教育機関や学校などで使用していた端末を利用者（生徒）が卒業に伴ってプライベート端末に転用する場合などに使う。N（携帯会社）では、レンタル品をセンターに返却する際にほかの企業で転用するために、対象企業の所有状態を外す目的で使用する |

#### フロー

8. **【K（ヘルプデスク）】受付管理簿 更新**
   - 受付管理簿に依頼内容を記録する
   - 記録項目：受付日、携帯電話番号、受付区分（故障フローの場合は「故障」を選択）、故障機のレンタル品管理No.・機種名・製造番号、申告内容・症状など
   - 交換品の発送後に発送日・伝票番号・交換品の機種名・製造番号を追記し、対応完了時に完了日を記録する

9. **【K（ヘルプデスク）→企業管理者】承り連絡** 📧
   - 依頼を正式に受け付けたことを企業管理者にメールで通知する（依頼元メールへの全返信）
   - これにより企業管理者は「依頼が受理された」ことを確認できる

10. **【企業管理者】確認**
    - 承り連絡の内容を確認する

11. **【K（ヘルプデスク）→N（レンタルセンター）】交換品手配** 📧
    - レンタルセンターに対し、交換用端末の準備・発送を依頼する
    - 「故障交換機器送付依頼書」（Excel）を添付して送信

12. **【N（レンタルセンター）】確認**
    - K（ヘルプデスク）からの依頼内容（機種・送付先など）を確認する

### Phase 4：交換品準備〜発送

#### このPhaseで登場する用語

| 用語 | 説明 |
|------|------|
| **キッティング** | 交換用の端末を利用者が業務で使える状態にセットアップする作業のこと。MDMプロファイルの投入、業務アプリの設定、各種ポリシーの適用、動作確認などを含む。端末の機種だけでなく、各企業・各部署ごとにキッティングの仕様（インストールするアプリ、適用する設定、制限ポリシーなど）が異なるため、依頼書のキッティング情報欄を参照して個別に対応する |
| **キッティング手順書** | キッティング作業の手順をまとめたマニュアル。端末の機種ごとだけでなく、各企業・各部署のキッティング仕様が異なるため、対象に応じた個別の手順書を印刷して作業に使用する |
| **レンタルあんしん補償オプション** | 携帯会社が提供する補償サービス。このオプションに加入していれば故障交換時の負担金が無料（ただし未返却時賠償金を除く）。未加入の場合はスマートフォン・タブレットで上限40,000円、ケータイ・データ通信製品で上限20,000円の負担金が発生する場合がある |

#### フロー

13. **【N（レンタルセンター）→K（ヘルプデスク）】交換品発送** 📦
    - レンタルセンターから交換品をK（ヘルプデスク）に発送する
    - 交換機器は同一機種同一色が原則だが、在庫状況によりレンタルセンターが同等と判断した機種への交換となる場合がある
    - 交換機器は未使用品に限らず、クリーニング・初期化済みの端末も含まれる

14. **【K（ヘルプデスク）】受領**
    - レンタルセンターから届いた交換品を受け取る

15. **【K（ヘルプデスク）】交換品準備**
    - 交換品および発送時に必要な物品を適宜準備する

> **備考：** 交換品および発送時に必要な物品を適宜準備します。
> - テプラ貼付（管理番号ラベルの貼り付け）
> - 同梱物（返送用レターパック等）の封入
> - ※本体のみの発送。付属品（充電器、ライトニングケーブル、フィルムなど）は同梱されないため、最寄りのショップ等で別途購入が必要

16. **【K（ヘルプデスク）】キッティング稼働確保**
    - キッティング作業を実施するための人員・時間を確保する

17. **【K（ヘルプデスク）】キッティング手順書印刷 / キッティング準備**
    - 該当企業・該当機種に応じたキッティング手順書を印刷し、キッティング作業の準備を行う

18. **【K（ヘルプデスク）】キッティング実施** （注2）
    - 交換用端末に対して**キッティング**を実施する
    - 依頼書のキッティング情報欄および該当企業のキッティング仕様に基づき、MDMプロファイルの投入、業務用アプリのインストール、各種設定の適用、動作確認などを行う

19. **【K（ヘルプデスク）】交換品発送準備**
    - 発送物の最終確認など、発送前の最終準備を行う

20. **【K（ヘルプデスク）→企業管理者】発送連絡** 📧
    - 交換品を発送した旨をメールで通知する（発送連絡メールへの全返信）

21. **【企業管理者】確認**
    - 発送連絡の内容を確認する

22. **【K（ヘルプデスク）】受付管理簿 更新**
    - 受付管理簿に発送日・伝票番号を記録する

23. **【K（ヘルプデスク）→企業管理者】発送** 📦
    - 交換用端末を宅配便で企業管理者宛に発送する

#### このPhaseの注記

| 注番号 | 内容 |
|--------|------|
| 注2 | 交換品の初期不良があった場合は、K（ヘルプデスク）にて交換品の再手配を行い、その旨を顧客へご連絡する |

### Phase 5：受領〜開通作業

#### このPhaseで登場する用語

| 用語 | 説明 |
|------|------|
| **物理SIM** | 従来型のSIMカード。端末のトレイに差し込んで使用する。故障交換時は旧端末からSIMカードを抜いて新端末に差し替える。eSIM端末の場合はこの差し替え作業は不要 |
| **プロファイルダウンロード** | eSIM利用時に、通信事業者から設定データを端末にダウンロードして通信を開通させる操作 |

#### フロー

24. **【利用者】受領** 📦
    - 宅配便で届いた交換品を受け取る

25. **【利用者】端末開通作業 / 適宜データコピー**
    - 届いた交換端末を使えるようにする作業を行う
    - 故障機が画面割れなどで操作自体が可能な場合は、連絡先・写真・ファイル等のデータを旧端末から交換端末に移行する

> **備考（端末開通作業について）：**
> - **物理SIMご利用の場合：** 旧端末からSIMカードを取り出し、交換端末のSIMトレイに挿入する
> - **eSIMご利用の場合：** 交換端末でプロファイルダウンロード（通信設定データの取得）を実施し、通信を開通させる（SIMカードの差し替え作業は不要）。なお、プロファイルダウンロードは利用者側で実施する場合と、K（ヘルプデスク）がキッティング時にあらかじめ実施する場合がある

### Phase 6：故障機のMDM/ABM操作代行〜故障機返却

#### このPhaseで登場する用語

| 用語 | 説明 |
|------|------|
| **MDM（Mobile Device Management）** | 企業が社員の端末を遠隔で一括管理するためのシステム。端末の設定配布、アプリ管理、紛失時のリモートロック・ワイプなどが可能。故障交換時は故障端末のライセンスを「デバイス削除」して管理対象から外す必要がある。故障時だけでなく、「盗難紛失した端末の再貸与」や「リクエストキッティング（誤って初期化した端末や利用者が変わる際の再キッティング）」の場合にもライセンス削除が必要。盗難紛失時は絶対ではないが、MDM上にゴミデータ（使われていない端末の管理情報）が残る原因となり、開発元も削除を推奨している。また、MDMの種類によってはライセンス数に応じた課金体系のものがあるため、不要なライセンスを残すとコスト増につながる点にも注意が必要 |
| **ABM** | Apple社が提供する法人向けの端末管理ツール。MDMと連動して、Appleアカウント・端末・アプリケーションを一元管理できる。依頼書に記載されたABM/ASM組織IDをもとに、K（ヘルプデスク）がキッティング時に交換端末を該当企業のABM環境へデバイス割り当て（MDM紐づけ）を行う。故障交換時に「所有状態の解除」を行うのは、携帯会社がレンタル品を回収した後に他の企業へ転用できるようにするため（詳細はPhase 3の受付管理簿「ABM/ASM代行操作」を参照） |
| **操作代行** | 本来は企業管理者が行うMDM/ABMの操作を、K（ヘルプデスク）（代理店）が代わりに実施するサービス |
| **未返却時賠償金** | 故障機の返却期限（交換機器受領後2週間以内）を過ぎても返却がない場合、または初期化されずに返却された場合に請求される賠償金。レンタルあんしん補償オプションの適用対象外 |

#### フロー

26. **【利用者→企業管理者】交換品の受領連絡** 📧
    - 交換品を受領したことを報告する

27. **【企業管理者】確認**
    - 利用者からの受領連絡の内容を確認する

28. **【企業管理者→K（ヘルプデスク）】MDM/ABM操作代行依頼** 📧
    - K（ヘルプデスク）にMDM/ABM操作代行を依頼する
    - 故障依頼時に作成した「故障交換機器送付依頼書」（注1）を添付する

29. **【K（ヘルプデスク）】受付**
    - MDM/ABM操作代行依頼を受領し、依頼元メールへの全返信で受付した旨を連絡する

30. **【K（ヘルプデスク）】MDM/ABM操作代行**
    - 以下の操作を代行して実施する
    - **MDM操作代行：** 故障端末のライセンスを「デバイス削除」し、MDM管理対象から外す。デバイス削除を行う主な理由は以下の2点。①利用者がステップ35で故障機を初期化する際に、制限プロファイル（端末の機能制限や操作制限をかける設定）が残っていると初期化が完了できないため、事前に削除しておく必要がある。②MDMの種類によってはライセンス数に応じた課金体系のものがあるほか、MDMから配信しているアプリ（Office 365などの有料アプリ）にもライセンス費用がかかるものがあるため、不要なライセンスを残すとコスト増につながる。また、削除しないとMDM上にゴミデータ（使われていない端末の管理情報）が残る原因にもなり、開発元も削除を推奨している
    - **ABM操作代行：** ABM上で故障端末の「所有状態の解除」を行う。これにより、携帯会社が故障機を回収後に他の企業へレンタル転用できるようになる

31. **【K（ヘルプデスク）→企業管理者】作業完了報告** 📧
    - 操作代行が完了したことをメールで報告する（承り連絡メールへの全返信）

32. **【企業管理者】確認**
    - 作業完了を確認する

33. **【企業管理者→利用者】故障機初期化 / 故障機発送指示** 📧
    - 利用者に対し、故障機の初期化と発送を指示する

34. **【利用者】確認**
    - 企業管理者からの指示内容を確認する

35. **【利用者】故障機初期化**
    - 故障端末のデータ消去（工場出荷状態への初期化）を行う
    - 個人情報やMDM情報を含む全ての情報・設定を消去する
    - 特にiOS端末の場合、「iPhoneを探す」を必ずオフにして返却する

36. **【利用者→N（レンタルセンター）】故障機発送** 📦
    - 故障した端末を交換機器送付時に同封されていた返送用レターパックでレンタルセンターに返却する
    - **端末（本体）のみ**を返却する（UIMカード・SDカード・アクセサリ類は取り外して返却しない）
    - 交換機器受領後**2週間以内**に返却する必要がある

37. **【N（レンタルセンター）】故障機受領** 📦
    - 返却された故障端末を受け取る

38. **【N（レンタルセンター）】故障機確認**
    - 返却された端末の状態（機種・シリアル番号の一致、初期化の有無、外観の確認など）を検品する

### Phase 7：未返却対応（例外フロー）

> ※ 故障機の返却期限（交換機器受領後2週間以内）を過ぎても返却がなかった場合に発動するフローです。

#### このPhaseで登場する用語

| 用語 | 説明 |
|------|------|
| **未返却時賠償金通知** | 故障機の返却期限を過ぎても返却がない場合（または初期化されずに返却された場合）に、レンタルセンターから届く賠償金の請求通知。レンタルあんしん補償オプションの適用対象外であり、ポイント利用も不可 |

#### フロー

39. **【N（レンタルセンター）】未返却** 
    - 返却期限を超過しても故障端末が返却されていないことを確認する

40. **【N（レンタルセンター）→K（ヘルプデスク）】未返却時賠償金通知連絡** 📧
    - 返却期限を超過した故障端末について、賠償金が発生する旨の通知が送付される

41. **【K（ヘルプデスク）】確認**
    - レンタルセンターからの通知内容を確認する

42. **【K（ヘルプデスク）→企業管理者】転送** 📧
    - レンタルセンターからの賠償金通知を企業管理者に転送する

43. **【企業管理者】未返却時賠償金通知 連絡受領** 📧
    - 賠償金通知を受領し、通知内容を確認する。速やかに故障機を返却するか、賠償金の支払い手続きを行う

44. **【N（営業担当）】情報共有** 📧 (CC)
    - 未返却時賠償金が発生している旨を、顧客の正式な対応窓口であるN（営業担当）が把握しておく必要があるため、一連の通知のやりとりがCCで共有される
