# リクエストキッティング対応フロー

## 概要

本フローは、企業が法人契約で利用している端末（iPhone / iPad / Android / ガラケー等）を誤って初期化してしまった場合や、端末の利用者が変更になった場合などに、再度キッティング（業務利用のためのセットアップ）を行う際の手順を定義したものです。
企業管理者による依頼書の作成・送付から、K（ヘルプデスク）でのキッティング実施、対象端末の返送・受領までの一連の流れを網羅しています。
故障交換とは異なり端末自体の交換は発生せず、対象端末をK（ヘルプデスク）へ送付してキッティングを施したうえで返送する流れとなります。

---

## 登場人物（スイムレーン）

| レーン | 説明 |
|--------|------|
| **利用者** | 実際に端末（iPhone / iPad / Android / ガラケー等）を業務で使用している社員。リクエストキッティングの当事者 |
| **企業管理者** | 法人契約の管理担当者。東日本・西日本支社の総務担当者など。利用者とK（ヘルプデスク）の間の窓口をつなぐ役割 |
| **K（ヘルプデスク）** | 携帯会社（N）から**再委託を受けている代理店**。依頼書の確認、端末のキッティング作業、MDM操作代行、受付管理簿の管理などを担当 |
| **N（営業担当）** | **携帯会社側の正規の顧客対応窓口（営業担当）**。K（ヘルプデスク）からの情報共有先として常にCCに入る。本フローでは直接的な作業担当はないが、顧客にとっての正式な対応窓口であるため、代理店（K）からの情報共有が必須 |
| **D（レンタルセンター）** | 携帯会社側の**物流・端末管理拠点**。本フローでは直接的な作業担当はない |

## フロー詳細

### Phase 1：依頼書の作成・送付〜受付

#### このPhaseで登場する用語

| 用語 | 説明 |
|------|------|
| **リクエストキッティング** | 誤って初期化した端末や利用者が変わる際に、再度キッティング（業務利用のためのセットアップ）を行うこと。故障交換とは異なり端末自体の交換は発生しない |
| **端末キッティング依頼書** | リクエストキッティングを依頼するための申請書（Excel形式）。「故障交換機器送付依頼書」や盗難紛失時に使用する「紛失時対応依頼書」とは別のフォーマットであり、本依頼書はリクエストキッティング専用である |
| **KIT（キッティング）** | 端末を利用者が業務で使える状態にセットアップする作業のこと。MDMプロファイルの投入、業務アプリの設定、各種ポリシーの適用、動作確認などを含む。端末の機種だけでなく、各企業・各部署ごとにキッティングの仕様（インストールするアプリ、適用する設定、制限ポリシーなど）が異なるため、依頼書のキッティング情報欄を参照して個別に対応する |
| **不備確認** | 依頼書の記載内容に誤り・漏れがないかチェックする作業。記入漏れ、契約名義と実際の契約の不一致、機種名の誤り、送付先住所の不備などを確認する |

#### フロー

1. **【企業管理者】端末キッティング依頼書の作成・送付** 📧📄（注1）
   - キッティングが必要な対象端末がある場合、「**端末キッティング依頼書**」（Excel形式）を作成する
   - 記入項目：ご依頼者様情報（ご契約者名・部署名・依頼者名・電子メール・連絡先・申告日）、キッティング情報（依頼種別〔ドロップダウンから選択〕・電話番号・機種名・キッティング情報1〜4）、端末機送付情報（送付先住所・宛名・電話番号）
   - 記入した依頼書をExcelファイルのままメールでK（ヘルプデスク）の指定メールアドレスへ送付する

2. **【K（ヘルプデスク）】受付**
   - 依頼書をメールで受領し、リクエストキッティング対応を開始する

3. **【K（ヘルプデスク）】不備確認**
   - 依頼書の記載内容に不備がないかをチェックする
   - **不備なし** → ステップ5（受付管理簿への記録）へ進む
   - **不備あり** → 企業管理者へ差し戻し（修正依頼）
   - チェック項目の例：記入漏れ、契約名義と実際の契約の一致、機種の正確性など

4. **【企業管理者】返却 / 修正**（不備ありの場合） 📧📄
   - K（ヘルプデスク）から指摘された不備箇所を修正し、依頼書を再送付する
   - 再送付後、K（ヘルプデスク）が改めて不備確認を実施する（ステップ3に戻る）

> **備考：** 「端末キッティング依頼書」に不備があるか確認し、必要に応じてお客様に連絡します。
> - 記入漏れ
> - 契約名義/機種確認
> - など

#### このPhaseの注記

| 注番号 | 内容 |
|--------|------|
| 注1 | キッティングが必要な対象端末がある場合は、「端末キッティング依頼書」（Excel）を作成し、K（ヘルプデスク）の指定メールアドレスへ送付する |

### Phase 2：受付管理簿〜承り連絡

#### このPhaseで登場する用語

| 用語 | 説明 |
|------|------|
| **受付管理簿** | 企業ごとに作成される、故障交換をはじめとする各種依頼を一元管理するための台帳（Excel形式）。管理簿は「受付管理簿」シート、「リスト」シートの2シートで構成される。受付管理簿シートの主な管理項目は、項番（通し番号）、受付日、キャンセル有無、携帯電話番号、受付区分、発送日、伝票番号、完了日、故障/紛失対応情報（レンタル品管理No.、故障機の機種名・製造番号、申告内容・症状、交換品の機種名・製造番号）、メモ欄/備考。受付区分（受付種別）はおおまかに「故障」「紛失・盗難」「リクエストキッティング」「MDM代行操作」「ABM/ASM代行操作」の5種類で分類される（案件や企業の契約形態によって細分化・変動する場合がある）。リストシートは受付管理簿シートの「受付区分」をドロップダウンで選択するためのもの |
| **MDM代行操作** | ※MDMの種類によって文言や機能に差分あり。主な代行操作の項目としては、<br>**デバイス削除：** 不要な端末のデータをMDMから削除する。<br>**プロファイル変更/削除：** 端末に配信する制限プロファイル等の内容を変更したり、削除する。<br>**アプリ配信/削除：** 新たにアプリを追加配信したり、不要なアプリを削除する。<br>**ユーザ登録/変更/削除：** ユーザ情報を新規で追加したり、既存のデータを修正したり、削除する |
| **ABM/ASM代行操作** | 主な代行操作の項目としては、<br>**MDMとデバイスの紐づけ/解除：** 顧客が契約しているMDMと端末を紐づけすることでADE（Automated Device Enrollment [旧称：DEP]）の機能を使用したり、別のMDMと紐づけるために現状のMDMとの紐づけを解除する。<br>**所有状態の解除：** 二度とその企業で同じ端末を利用しない場合に管理下から削除する。教育機関や学校などで使用していた端末を利用者（生徒）が卒業に伴ってプライベート端末に転用する場合などに使う。D（携帯会社）では、レンタル品をセンターに返却する際にほかの企業で転用するために、対象企業の所有状態を外す目的で使用する |

#### フロー

5. **【K（ヘルプデスク）】受付管理簿 更新** 📄
   - 依頼書に不備がないことを確認後、受付管理簿に依頼内容を記録する
   - 記録項目：受付日、携帯電話番号、受付区分（リクエストキッティングフローの場合は「リクエストキッティング」を選択）、機種名など
   - 対応完了時に発送日・伝票番号・完了日を追記する

6. **【K（ヘルプデスク）→企業管理者】承り連絡** 📧
   - 依頼を正式に受け付けたことを企業管理者にメールで通知する（依頼元メールへの全返信）
   - これにより企業管理者は「依頼が受理された」ことを確認できる
   - 併せて、対象端末の初期化・発送に関する案内を行う

7. **【企業管理者】確認**
   - 承り連絡の内容を確認する

### Phase 3：対象端末の初期化・発送〜受領

#### このPhaseで登場する用語

| 用語 | 説明 |
|------|------|
| **SIMカード（UIMカード）** | 端末に挿入する小さなICカード。電話番号や契約情報が記録されており、これがないと通話・通信ができない。依頼書上では「UIMカード」と表記される。故障交換時は旧端末からSIMカードを抜いて新端末に差し替えて使用する。盗難紛失で端末ごとSIMカードを喪失した場合は、N（営業担当）が再発行手続きを行う。再発行手数料は3,850円（税込）※2025年9月5日以降は4,950円（税込）に改定。ただし故障交換を伴うeSIM再発行については手数料不要 |
| **eSIM** | 端末本体に内蔵された電子的なSIM。物理的なカードの差し替えが不要で、プロファイル（設定データ）をダウンロードして開通する。eSIM端末の場合、故障交換時もSIMカードの差し替え作業は不要。盗難紛失時はN（営業担当）がeSIMの再発行手続きを行う |

#### フロー

8. **【企業管理者】対象端末の初期化**
   - 対象端末を工場出荷状態に初期化する
   - 初期化ができない場合は、手動削除可能なデータをあらかじめ削除しておく

9. **【企業管理者→K（ヘルプデスク）】対象端末の発送** 📦📄（注2）
   - 初期化済みの対象端末をK（ヘルプデスク）宛に宅配便で発送する
   - 送付物：
     - 端末キッティング依頼書（本紙）
     - 対象端末
     - 物理SIM（物理SIMの場合のみ）
   - 端末送付時にかかる送料等の費用はお客様（企業管理者側）負担となる

10. **【K（ヘルプデスク）】受領** 📦
    - 企業管理者から発送された対象端末および同封書類を受け取る
    - 端末キッティング依頼書と実際の端末の照合を行う

#### このPhaseの注記

| 注番号 | 内容 |
|--------|------|
| 注2 | 端末キッティング依頼書を同封してください。SIM送付は物理SIMの場合のみ。端末送付時にかかる送料等の費用はお客様負担 |

### Phase 4：キッティング作業〜返送

#### このPhaseで登場する用語

| 用語 | 説明 |
|------|------|
| **MDM（Mobile Device Management）** | 企業が社員の端末を遠隔で一括管理するためのシステム。端末の設定配布、アプリ管理、紛失時のリモートロック・ワイプなどが可能。リクエストキッティング時には、旧MDMデバイス情報の「デバイス削除」が必要となる場合がある。削除しないとMDM上にゴミデータ（使われていない端末の管理情報）が残る原因となり、開発元も削除を推奨している。また、MDMの種類によってはライセンス数に応じた課金体系のものがあるため、不要なライセンスを残すとコスト増につながる |
| **KIT手順書** | キッティング作業の手順をまとめたマニュアル。端末の機種ごとだけでなく、各企業・各部署のキッティング仕様が異なるため、対象に応じた個別の手順書を印刷して作業に使用する |
| **プロファイルダウンロード** | eSIM利用時に、通信事業者から設定データを端末にダウンロードして通信を開通させる操作。eSIM端末の場合、K（ヘルプデスク）がキッティング時にあらかじめ実施する |

#### フロー

11. **【K（ヘルプデスク）】対象端末の準備**
    - 受領した対象端末およびキッティングに必要な物品を適宜準備する

> **備考：** 対象端末および発送時に必要な物品を適宜準備します。
> - テプラ貼付（管理番号ラベルの貼り付け）
> - 同梱物の準備
> - など

12. **【K（ヘルプデスク）】キッティング稼働確保**
    - キッティング作業を実施するための人員・時間を確保する

13. **【K（ヘルプデスク）】対象端末のMDMデバイス削除**
    - 対象端末に紐づいている旧MDMデバイス情報を削除する
    - キッティング前の前処理として、MDM上の古いデータを除去し、新規キッティングの準備を行う

14. **【K（ヘルプデスク）】キッティング手順書印刷 / キッティング準備**
    - 該当企業・該当機種に応じたKIT手順書を印刷し、キッティング作業の準備を行う

15. **【K（ヘルプデスク）】KIT実施**
    - KIT手順書に基づいて、対象端末のキッティング作業を実施する
    - 依頼書のキッティング情報欄および該当企業のキッティング仕様に基づき、MDMプロファイルの投入、業務用アプリのインストール、各種設定の適用、動作確認などを行う
    - 対象端末が未初期化の場合、K（ヘルプデスク）にて初期化を実施する場合がある（データ復元は不可）
    - eSIM端末の場合、プロファイルダウンロードもキッティング時に実施する

> **備考：**
> - 対象端末が未初期化の際、K（ヘルプデスク）にて初期化を実施する場合があります。データ復元はできませんのでご注意ください。
> - eSIM端末のプロファイルダウンロードはキッティング時に実施します。

16. **【K（ヘルプデスク）】発送準備**
    - キッティング完了後、対象端末の返送準備を行う
    - 端末キッティング依頼書に記載された送付先情報に基づき、梱包・伝票作成を行う

17. **【K（ヘルプデスク）→企業管理者】発送連絡** 📧
    - 対象端末を発送した旨をメールで通知する（承り連絡メールへの全返信）
    - 伝票番号等の配送追跡情報を併せて案内する

18. **【企業管理者】確認**
    - 発送連絡の内容を確認する

19. **【K（ヘルプデスク）→企業管理者】対象端末の発送** 📦
    - キッティング済みの対象端末を、端末キッティング依頼書に記載された送付先宛に宅配便で発送する

20. **【K（ヘルプデスク）】受付管理簿 更新** 📄
    - 受付管理簿の該当案件に発送日・伝票番号・完了日を記入し、対応をクローズする

21. **【企業管理者】受領** 📦
    - K（ヘルプデスク）から返送されたキッティング済み端末を受け取る
    - 利用者へ端末を引き渡し、業務利用を再開する
