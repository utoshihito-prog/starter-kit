### 進め方

2. 完了したらチェックボックスを `[x]` に更新
3. テスト・リント合格を確認してコミット

## コンテキスト管理
- コンテキスト使用率は40%以下を維持する
- 40%を超えたらタスクをまとめて新セッションを開始する
- コンテキストの長さを理由にショートカットしない。要約を早めない。タスクは完全に終わらせる
- 途中で切り上げるくらいなら、新しいセッションを提案する
- 1タスク = 1セッションが基本。タスクが変わったら新しい会話を始める
- 大量のトークンを消費する操作の前に警告する

## 言葉遣い
- 中学生・高校生にも分かる日本語で
- 冗長な長文は禁止。簡潔に

## Git
- コミットメッセージは日本語。形式: <種別>: <内容>
- 種別: feat / fix / refactor / test / docs / chore
- 1タスク = 1コミット
- コミット前に検証を実行

## コーディング規約
- 使用言語の strict mode を有効にする
- 型安全: 曖昧な型は避ける。具体的な型を使う
- ファイル名: 言語の慣例に従う
- インポート順序: 外部 → 内部 → 型 → スタイル
- 未使用のインポート・変数は即削除
- 関数は短く。1つの関数は1つの仕事だけ
- 既存のパターンに従う。新パターンを導入する前に既存を確認

## 安全
- ファイル削除前に確認
- .env をコミットしない
- テスト未通過でコミットしない
- 破壊的操作は許可なく実行しない

## 安全境界
慎重に扱う領域:
- 認証・認可・課金・権限
- DB schema / migration
- CI/CD パイプライン
- 本番環境の設定・シークレット
上記を変更する場合は計画を作って人間に確認する。
