## 最優先ルール（これを無視するな）

1. **スキルファイルに従え**: ユーザーが `/スキル名` と言ったら `.agents/skills/スキル名/SKILL.md` を読み、その手順通りに実行しろ。自分の判断で省略するな
2. **勝手に進めるな**: 成果物を出したら必ず人間に見せて「これでいいですか？」と聞け。承認されるまで次に進むな
3. **一度に全部やるな**: brainstorm → spec → plan → execute は1ステップずつ。まとめてやるな

## フェーズゲート

```
[Brainstorm] → 人間が「OK」と言ったら →
[Spec]       → 人間が「OK」と言ったら →
[Plan]       → 人間が「OK」と言ったら →
[Execute]    → 差分ごとに検証 →
[Review]     → 人間が確認 →
[Ship]
```

禁止:
- spec が承認されていないのに plan を作ること
- plan が承認されていないのにコードを書くこと
- 人間が「進めて」と言っていないのに次フェーズに行くこと
- 例外: 人間が「全部一気にやって」と言った場合のみスキップ可

## スキルの実行方法

1. `.agents/skills/スキル名/SKILL.md` を開いて読む
2. そこに書いてある手順を上から順に実行する
3. 定義された出力フォーマットで結果を返す
4. 手順を飛ばさない

## 初回セットアップ時

プロジェクトに初めて触る場合:
1. まずこのファイルを最後まで読む
2. docs/ フォルダの中身を確認する
3. 何が存在して何が未作成かを人間に報告する
4. 人間の指示を待つ（勝手に作り始めない）

## ルール

- まず計画を立てる。複数ファイルを変える作業は必ず plan を作ってから
- 最小の正しい差分を出す。動いてるコードを理由なく書き直さない
- 成功を宣言する前に検証する。scripts/verify.sh があればそれを使う
- 既存のパッケージマネージャとタスクランナーに従う
- 必要なければ依存パッケージを追加しない
- 迷ったら docs/ を読んでからコードを触る

## コンテキスト管理

- コンテキスト使用率は40%以下を維持する
- 40%を超えたらタスクをまとめて新セッションを開始する
- 1タスク = 1セッションが基本
- 大量のトークンを消費する操作の前に警告する

## 言葉遣い

- 中学生・高校生にも分かる日本語で
- 冗長な長文は禁止。簡潔に

## Git

- コミットメッセージは日本語。形式: <種別>: <内容>
- 種別: feat / fix / refactor / test / docs / chore
- 1タスク = 1コミット
- コミット前に検証を実行
