# バグ診断

バグの原因を体系的に見つけて、修正案と回帰テストを提案する。

## 手順

### ステップ1: 症状の確認
1. $ARGUMENTS の症状を整理する
2. 再現手順を特定する:
   - どういう操作で起きるか
   - エラーメッセージの全文を確認する
   - いつから起きているか（常に？最近？）

### ステップ2: 最近の変更を確認
1. `git log --oneline -10` で最近のコミットを確認する
2. 症状が最近から始まった場合: `git bisect` で原因コミットを特定する
3. 関連しそうなコミットの差分を `git show <hash>` で確認する

### ステップ3: 原因の調査
1. エラーメッセージから関連ファイルを特定する
2. データの流れを追う（入力 → 処理 → 出力）
3. 仮説を立てる:
   - 仮説1: [具体的な仮説]
   - 仮説2: [具体的な仮説]
4. コードを読んで仮説を検証する

## 修正案

### Before (問題のコード)
```[lang]
// ファイル: src/xxx.ts:42
[問題のコード]
```

### After (修正後)
```[lang]
// ファイル: src/xxx.ts:42
[修正コード]
```

## 回帰テスト
```[lang]
it('修正内容を検証するテスト', () => {
  // テストコード
})
```
```

### ステップ5: 修正の適用
1. ユーザーに修正案を確認してから適用する
2. テストを実行して修正が正しいことを確認する
3. 回帰テストを追加する

## 失敗時の対処

| 状況 | 対処 |
|------|------|
| 再現できない | 環境の違い（OS、Node.jsバージョン等）を確認。ログ追加を提案 |
| 原因が複数の可能性 | 各仮説の確率と検証方法を提示。ユーザーに追加情報を聞く |
| 外部依存の問題 | APIの障害、パッケージのバグ等。ワークアラウンドを提案 |
| テストがない | 修正前にまずテストを書いて現在の動作を記録する |
