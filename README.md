# Vibe Coding Starter Kit

AIと一緒に開発する時に「毎回同じ説明するのめんどくさい」を解決するキット。

---

## こんな悩みありませんか？

- 毎回ファイル構成やルールをイチから説明してる
- 開発の途中で進捗がわからなくなる
- エージェントが終わったか分からなくて画面を見張ってる

**全部このキットで解決します。**

---

## キットの構成

このキットは **エディタ（開発ツール）ごとにフォルダが分かれています**。
自分が使うエディタのフォルダだけ取り出して使います。

> **大事なポイント**: ここで選ぶのは「エディタ（開発ツール）」であって「AIモデル」ではありません。
> 例えば Antigravity で Claude モデルを使う場合、選ぶのは「Antigravity」です。

```
starter-kit/
├── shared/             ← 全エディタ共通（必ず使う）
├── editors-claude/     ← Claude Code 用
├── editors-cursor/     ← Cursor 用
├── editors-windsurf/   ← Windsurf 用
├── editors-gemini/     ← Gemini CLI / Antigravity 用
├── editors-codex/      ← Codex 用
└── setup.sh            ← 対話式セットアップ
```

**shared/ は必ず必要**。それに加えて、自分が使うエディタのフォルダを取り出す。

---

## 対応エディタ

| エディタ | 種類 | setup.sh での名前 |
|---------|------|-----------------|
| Claude Code | ターミナルCLI | `claude-code` |
| Cursor | VS Code系AI IDE | `cursor` |
| Windsurf | VS Code系AI IDE | `windsurf` |
| Antigravity | GoogleのAI IDE | `antigravity` |
| Gemini CLI | ターミナルCLI | `gemini-cli` |
| Codex (OpenAI) | ターミナルCLI | `codex` |

> **エディタとモデルは別物です。**
> - エディタ = コードを書く道具（VS Code的なもの）
> - モデル = AIの頭脳（Claude, Gemini, GPT等）
>
> どのエディタでも複数のモデルが使えます。
> Antigravity で Claude を使っても、選ぶのは `antigravity` です。

## 始め方

### 方法 1: 対話モード（おすすめ）

```bash
# starter-kit フォルダに移動してから実行
cd Desktop/starter-kit
bash setup.sh my-app    # ← "my-app" は好きなプロジェクト名に変えてOK
```

番号を選ぶだけ:

```
┌─────────────────────────────────────────┐
│  どのエディタで開発しますか？            │
│  （複数選べます。番号をスペース区切り）  │
└─────────────────────────────────────────┘

  1) Claude Code      … ターミナルで動くCLI
  2) Cursor           … VS Code系のAI IDE
  3) Windsurf         … VS Code系のAI IDE
  4) Antigravity      … GoogleのAI IDE
  5) Gemini CLI       … ターミナルで動くCLI
  6) Codex            … OpenAIのCLI

番号を入力 (例: 1 or 1 2):
```

### 方法 2: コマンドで直接指定

```bash
cd Desktop/starter-kit
bash setup.sh my-app claude-code
bash setup.sh my-app antigravity
bash setup.sh my-app claude-code cursor   # 複数併用
```

### 方法 3: エージェントに頼む（初心者向け）

**まずターミナルで setup.sh を実行してから**、エージェントを起動してください:

```bash
# 1. まずターミナルで実行（エージェントにやらせない）
cd Desktop/starter-kit
bash setup.sh my-app

# 2. プロジェクトフォルダに移動してエディタを起動
cd my-app
```

エディタが開いたら、こう言うだけ:

> このプロジェクトを初期化して。/init-project の手順に従って

### 初めて使う時のコツ

最初からエージェントに全部任せなくていい。段階的に信頼を築くのがおすすめ:

1. **まず質問してみる** — 「このプロジェクトの構成を説明して」と聞いて、答えの精度を確認
2. **小さいタスクを頼む** — 「この関数にテストを追加して」等、影響範囲が小さいもの
3. **徐々に任せる範囲を広げる** — 精度に満足したら、機能追加やリファクタを任せる

## 初期化の流れ

`/init-project` を実行すると、2つ聞かれます:

```
1. 要件定義のファイルはありますか？ → ある / ない
2. 壁打ち（対話で深掘り）しますか？  → する / しない
```

| パターン | 流れ |
|---------|------|
| ファイルあり + 壁打ちなし | ファイルを読んで自動設定 → すぐ生成 |
| ファイルあり + 壁打ちあり | ファイルをベースに「ここは本当にこれでいい？」を対話で深掘り → 生成 |
| ファイルなし + 壁打ちなし | 5つの質問に答える → 生成 |
| ファイルなし + 壁打ちあり | ゼロから「誰が困ってる？」「どう解決する？」を対話で整理 → 生成 |

壁打ちした場合は要件定義書 (docs/requirements.md) も自動で保存されます。

ファイルがない場合は5つ聞かれます:

```
1. プロジェクト名は？        → 予約管理アプリ
2. 何を作る？（一言で）       → 美容院の予約をネットで受け付ける
3. 技術スタック？             → Next.js + Supabase
4. どんな画面がある？(3〜5個) → 予約カレンダー、予約フォーム、管理画面
5. デプロイ先は？             → Vercel
```

どちらの場合でも、これが全部自動で作られます:
- 設計書 (docs/architecture.md)
- タスク一覧 (docs/tasks.md) ← チェックボックス付き
- GitHubリポジトリ
- ルール・スキル42個

**あとは「始めて」と言うだけ。**

## 開発中にできること

エージェントにこう言うだけで使えます。コマンドを覚える必要はありません。

| こう言えば | やってくれること |
|-----------|---------------|
| 「進捗見せて」 | いま何%終わったか進捗バーで見せてくれる |
| 「バックアップして」 | GitHubに保存してくれる |
| 「コミットして」 | 変更内容を見てコミットメッセージを作ってくれる |
| 「コードレビューして」 | 問題点をチェックして重要度別に教えてくれる |
| 「検索機能を計画して」 | タスクに分けて計画を立ててくれる（コードは書かない） |
| 「このバグ直して: ○○」 | 原因を見つけて直し方を出してくれる |
| 「セキュリティチェックして」 | 脆弱性がないか調べてくれる |
| 「テスト作って」 | 既存コードに合わせてテストを自動生成 |
| 「Dockerファイル作って」 | プロジェクトに合ったDockerfileを作ってくれる |
| 「CI/CD設定して」 | GitHub Actionsの設定を自動生成 |

> `/` を押すと全42コマンドが日本語の説明付きで出ます。

---

## チーム開発

HP制作やシステム開発で、フロント・バック・デザインを分けて進めたい時:

> 「チーム開発モードで始めて」

エージェントが「何を作る？」と聞いてきて、役割を振り分けて順番に進めてくれます。

---

## 引き継ぎ

途中で別の人やエージェントに渡したい時:

> 「引き継ぎ資料を作って」

HANDOFF.md が自動で作られます。引き継いだ人は:

> 「このプロジェクトを引き継いだ。HANDOFF.md を読んで再開して」

## 全42スキル

### 管理

| コマンド | やること |
|---------|---------|
| `/init-project` | 質問に答えるだけでプロジェクトを丸ごと作る |
| `/progress` | いま何%終わったか進捗バーで見る |
| `/backup` | GitHubにバックアップする |
| `/save-skill` | 便利だったやり方をスキルとして保存する |
| `/sync-agents` | ルールを全エージェントに反映する |
| `/handoff` | 別の人やエージェントに引き継ぐための資料を作る |
| `/resume` | 引き継ぎ資料を読んで開発を再開する |
| `/taskboard` | チェックボックス付きタスク一覧を作ってリアルタイム更新する |
| `/team-start` | チーム開発モードで始める。役割を振り分けて進める |
| `/team-status` | 各担当の進捗をまとめて報告する |
| `/autopilot` | 計画の承認後、ゴールまで全自動で走る（起動時に確認あり） |

### 品質

| コマンド | やること |
|---------|---------|
| `/review` | コードの問題点をチェックして重要度別に報告する |
| `/security-check` | セキュリティの穴がないか調べる |
| `/test-gen` | 既存コードに合わせてテストを自動で作る |
| `/commit` | 変更内容からコミットメッセージを作って確認後コミットする |
| `/polish` | さっき書いたコードをもう一回見直してシンプルにする |
| `/dead-code` | 使ってないコードを見つけて消す |
| `/land` | テスト→リント→コミット→push→次タスク提案まで全自動で締めくくる |

| コマンド | やること |
|---------|---------|

| `/pr` | プルリクエストを作る |
| `/brainstorm` | コードを書く前にアイデアを深掘りする |

### セキュリティ
