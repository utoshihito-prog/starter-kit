# 仕様書作成

brainstorm や要件をもとに、Claude が理解した内容を仕様書にまとめる。
「認識のズレ」をコードを書く前に潰すためのステップ。

## 手順

1. 入力を確認:
   - /brainstorm の結果がある場合はそれを読む
   - docs/product.md がある場合はそれも読む
   - $ARGUMENTS が指定されている場合はそのテーマで

2. 以下の構成で仕様書を作成:

   ## 何を作るか（一言）
   ## ユーザーから見える動作
   - 画面/操作ごとに「ユーザーが○○すると、○○が起きる」
   ## 技術的な制約
   - 使う技術、外部API、パフォーマンス要件
   ## エッジケース
   - 正常系以外で考慮すべきケース
   ## やらないこと
   - スコープ外を明記
   ## 受け入れ条件
   - これが全部満たされたら完成

3. docs/spec.md に保存

4. ユーザーに確認: 「この仕様で合ってますか？修正があれば教えてください」

5. 確認後: 「/plan でタスク分解しますか？」と提案
