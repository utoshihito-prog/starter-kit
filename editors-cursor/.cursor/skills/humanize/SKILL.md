# AI文章の自然化

AI臭い文章を自然な日本語に書き直す。

## 手順

### ステップ1: 対象テキストの受け取り

- ユーザーがテキストを貼り付けるか、ファイルを指定する
- ファイルの場合はコードコメント以外のテキスト部分を対象にする

### ステップ2: AI臭さの検出

#### 表面的なパターン（見つけやすい）

| パターン | 例 | 問題 |
|---------|-----|------|
| 接続詞の多用 | 「なお」「また」「さらに」の連続 | 箇条書きで十分 |
| 過剰な丁寧語 | 「〜させていただきます」 | 「〜します」で十分 |
| 抽象的修飾語 | 「包括的に」「網羅的に」「シームレスに」 | 具体的な言葉に |
| 同じ構文の繰り返し | 「○○は△△です。○○は△△です。」 | 文のリズムを変える |

#### 本質的なパターン（AI臭さの根本原因）

| パターン | 例 | 修正方針 |
|---------|-----|---------|
| 具体性の欠如 | 「様々な改善を行いました」 | 何を何件改善したか |
| 主張の不在 | 「○○と言えるかもしれません」 | 「○○です」と言い切る |
| 均一な文のリズム | 全文が「AはBです」形式 | 短文・体言止め・問いかけを混ぜる |
| 網羅的な列挙 | 「A、B、C、D、E等があります」 | 重要な2〜3個に絞る |
| 感情の不在 | 事実の羅列のみ | 「正直これは驚いた」等の一人称を入れる |

### ステップ3: トーンの選択

| トーン | 用途 | 特徴 |
|--------|------|------|
| カジュアル | ブログ、SNS | 話し言葉、一人称「僕/私」 |
| ビジネス | メール、報告書 | 丁寧だが簡潔。「〜です/ます」 |
| テックブログ | 技術記事 | 専門用語OK、体験ベース |
| ドキュメント | 公式文書 | 正確で簡潔。感情は入れない |

ユーザーに「どのトーンで書き直しますか？」と聞く。指定がなければテキストの用途から推測する。

### ステップ4: 書き直しと出力

Before/After で比較できる形式で出力する:

```
### Before
様々な最適化を包括的に行うことで、パフォーマンスの大幅な改善を実現いたしました。
なお、今後も継続的に改善を進めてまいります。

### After
ページの読み込み時間を3秒→0.8秒に短縮しました。
主な改善点は画像の遅延読み込みとAPIレスポンスのキャッシュです。

### 変更ポイント
- 「様々な最適化を包括的に」→ 具体的な施策名に
- 「大幅な改善」→ 数値で示す
- 「なお」の接続詞を削除
- 「〜いたしました」→「〜しました」
```

### ステップ5: ユーザーに確認

「この書き直しでいいですか？調整があれば教えてください」と確認する。

## エッジケース

| 状況 | 対処 |
|------|------|
| 技術文書 | 正確さが最優先。感情は入れない。用語は変えない |
| コードコメント | 簡潔さが最優先。「〜する」の体言止めでOK |
| 既に自然な文章 | 「特に修正の必要はありません」と伝える |
| 英語テキスト | 「日本語のテキストを対象としています」と伝える |
