# コード磨き上げ

最近変更したコードを別の視点で見直して、シンプルにできるところを見つける。

## 手順

### ステップ1: 最近の変更を取得
1. `git diff HEAD~1` で直近のコミットの変更を取得する
2. 差分が空の場合:
   - `git diff` で未コミットの変更を確認する
   - それも空なら `git diff HEAD~3` で直近3コミットを確認する
   - それでも空なら「磨き上げる変更がありません」と伝えて終了する

### ステップ2: 以下の観点でチェック

| 観点 | 具体例 |
|------|--------|
| シンプルさ | 三項演算子の方がすっきり、early return でネスト削減 |
| 重複 | 2箇所で同じコードを書いている |
| 不要な抽象化 | 1回しか使わないのに関数化・クラス化している |
| 変数名・関数名 | `data` → `userList`、`handle` → `handleSubmit` |
| マジックナンバー | `if (items.length > 10)` → `const MAX_ITEMS = 10` |
| コメント | 明らかなことにコメント付けている、逆に複雑なのに説明がない |

### ステップ3: 改善案を提示

```
## 磨き上げ提案

| # | ファイル | 行 | 観点 | Before | After |
|---|---------|-----|------|--------|-------|
| 1 | src/api/users.ts | 15-25 | ネスト削減 | if-else 3段 | early return |
| 2 | src/utils/format.ts | 8 | 命名 | `fmt` | `formatDate` |
| 3 | src/hooks/useAuth.ts | 30,55 | 重複 | 同じfetch処理 | 共通関数に抽出 |

### 提案1: ネスト削減 (src/api/users.ts:15-25)

Before:
```ts
[変更前]
```

After:
```ts
[変更後]
```
```

### ステップ4: 修正の適用
1. ユーザーが承認した提案だけ修正する
2. 修正後にテストを実行して動作が変わっていないことを確認する

## エッジケース

| 状況 | 対処 |
|------|------|
| 変更が大きすぎる（100行超） | 重要度の高い上位5件に絞る |
| テストがない | 「テストなしで変更するリスクがあります」と警告 |
| 既にきれいなコード | 「特に改善点はありません」と正直に伝える |
