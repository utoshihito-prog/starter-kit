# 更新履歴生成

gitのコミット履歴から、ユーザー向けの更新履歴を生成する。

## 手順

### ステップ1: 前回リリースの特定

以下の優先順位で「前回のリリース」を特定する:

1. `git tag --sort=-creatordate` でタグ一覧を取得する
   - セマンティックバージョニングのタグがあれば最新を使う
2. タグがない場合: CHANGELOG.md の最新日付を確認する
3. どちらもない場合: ユーザーに聞く
4. 初回リリースの場合: 全コミットを対象にする

### ステップ2: コミットの収集と分類

1. `git log [前回タグ]..HEAD --oneline` でコミット一覧を取得する
2. 各コミットを分類する:

| カテゴリ | コミット種別 | CHANGELOGに含める |
|---------|------------|-----------------|
| 新機能 | feat | ○ |
| バグ修正 | fix | ○ |
| 改善 | refactor, perf | ○ |
| その他 | chore, docs, test | × (通常) |

3. 技術的すぎる表現をユーザー向けに変換する:
   - Before: `fix: null check in auth middleware`
   - After: ログイン時にエラーになる問題を修正

### ステップ3: バージョン番号の提案

| 変更内容 | バージョン | 例 |
|---------|----------|-----|
| 破壊的変更 | メジャー (X.0.0) | APIの仕様変更 |
| 新機能追加 | マイナー (x.X.0) | 新しい画面 |
| バグ修正のみ | パッチ (x.x.X) | エラー修正 |

### ステップ4: CHANGELOG.md に追記

Keep a Changelog 形式で出力する:

```markdown
## [1.2.0] - 2026-03-30

### 新機能
- 商品の検索機能を追加しました
- お気に入りリストを保存できるようになりました

### バグ修正
- ログイン時にエラーが出る問題を修正しました

### 改善
- 商品ページの表示速度を改善しました
```

## エッジケース

| 状況 | 対処 |
|------|------|
| タグもCHANGELOGもない | 全コミット対象。「初回リリースですね」と案内 |
| コミットが0件 | 「更新がありません」で終了 |
| コミットメッセージが雑 | 差分の内容から推測して書き直す |
| モノレポ | 「どのパッケージのCHANGELOGですか？」と聞く |
